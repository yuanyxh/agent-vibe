# 回归示例：红警类 RTS

用于验证 init 在“我想做一个红警”这类需求下不会被技术栈问题带走。

## 用户

> 我想做一个红警类的游戏。

## 正确的 init 行为

### 第 1 轮：定位

- 项目名与一句话目标
- 形态：Web / 桌面 / 主机
- 规模：原型 / MVP / 完整
- 领域：游戏 / RTS

### 第 2 轮：领域最低必问项

| 问题 | 为什么不能跳过 |
| --- | --- |
| 单机还是联机 | 决定架构、同步、服务器与测试方式 |
| 目标平台与设备 | 决定引擎、输入与性能基线 |
| 素材来源与版权 | 决定能否使用原版资源，还是必须原创 |
| MVP 范围 | 阵营、单位、建筑、关卡、地图数量 |
| 输入设备 | 键鼠、触控、手柄 |
| 性能目标 | 单位数量、帧率、加载时间 |
| 存档与进度 | 是否需要持久化与恢复 |
| 发布方式 | 网页、安装包、商店 |

### 第 3 轮：技术栈与交付

只有在定位与领域问题确认后，才问语言、引擎、构建、测试与发布。

### 第 4 轮：质量与治理

测试级别、性能预算、许可证、素材声明、供应链。

### 完备性门

输出检查表，确认以下项均有值或明确推断：

- 画像必填字段
- 领域最低必问项
- 开发环境与目标环境
- 构建、测试、发布
- 许可证与素材来源

## 错误行为

- 用户说“做红警”，只问“用什么技术栈/引擎”。
- 问完技术栈就直接给方案或写代码。
- 没有画像、领域定义、规则与质量门。
- 没有确认素材版权与 MVP 范围。

## 验收

出现“只问技术栈就开工”即判定 init 入口或完备性门失效。
