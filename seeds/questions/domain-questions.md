# 领域最低必问项

领域定义可以现场生成，但以下问题必须进入提问队列，不能因为先问了技术栈就跳过。

| 领域 | 必问 |
| --- | --- |
| 游戏 / 3D | 单机还是联机；目标平台与设备；素材来源与版权；MVP 范围（阵营、单位、建筑、关卡）；输入设备；性能目标；存档与进度；发布方式 |
| 官网 / 内容站 | 目标搜索引擎与地区；内容由谁维护；是否需要多语言；分析与 Cookie 合规；分享与结构化数据 |
| 管理后台 / SaaS | 角色与权限边界；关键业务路径；数据量级；是否需要审计；多语言与终端适配 |
| 后端 / API | 调用方与信任边界；并发与一致性要求；可接受中断与数据丢失窗口；认证与授权；容量与限流 |
| CLI | 人工、脚本还是 CI；目标操作系统与终端；是否需要交互模式；配置优先级 |
| 库 / SDK | 使用者语言与运行时范围；兼容性承诺；发布节奏；是否需要多包管理 |
| 移动 | 目标平台与最低系统版本；离线能力；系统权限；发布渠道与审核要求 |
| 桌面 | 目标操作系统；签名与公证；更新通道与回滚；系统权限 |
| 三方集成 | 对端契约与版本；延迟与失败处理；回调验签；对账；沙箱与生产隔离 |

## 使用

1. 画像确定 `project.domain` 后，读取对应行的必问项。
2. 每项要么有用户回答，要么标注为推断并说明依据。
3. 必问项未覆盖时，不得进入生成阶段。

## 禁止

- 只问技术栈就开工。
- 把领域必问项交给“后续再说”。
- 用默认值掩盖关键业务选择（单机/联机、版权、发布方式）。
