# Agent 资产盘点

## 要保证的结果

生成基座前知道手上已有什么、哪些能用、哪些会冲突，避免重复生成或覆盖既有约定。

## 判断标准

- 项目级资产优先于用户级与第三方资产。
- 冲突时以用户当前说明和项目规则为准，不静默覆盖。
- 第三方资产先核对来源、许可、维护状态与安全边界，再决定是否采纳。
- 只记录名称、结论与理由，不复制内容，不执行来源不明的脚本。

## 实例化步骤

1. 按适配器列出的位置盘点项目级技能、规则、命令、子代理与契约。
2. 只读用户级与插件资产的名称和描述，不写入项目。
3. 记录可用 MCP 工具及其权限与数据边界。
4. 逐项给出采纳、改造或忽略，并说明适用性与冲突。
5. 把结论写入 `.agent/research.md` 的资产盘点部分。

## 反例

- 未盘点就生成与现有 skill 重名的技能。
- 直接复制用户级规则或第三方技能内容进项目。
- 采纳来源不明、长期未维护或权限过宽的插件。
- 在文档中记录个人目录或内部地址。

## 边界

本能力负责生成前的初始盘点。生成后的周期性体检、腐化检测与合并整理属于 `capability/agent-environment`。
