# 记忆

## 目标

让关键事实跨会话保留，同时避免记忆变成不可核实的“第二真相”。

## 分层

默认写入项目，外部服务只作为可选增强。

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 项目状态 | `.agent/status.md`、`decisions.md` | 当前目标、进度、决策与回退 |
| 项目教训 | `.agent/lessons.md` | 有证据的缺陷根因与经验 |
| 长期记忆 | `.agent/memory/INDEX.md` 与主题文件 | 长期事实、用户偏好与领域约束 |
| 跨项目记忆 | 环境提供的外部服务（可选） | 脱敏后的可复用模式 |

## 条目与引用

- 每条记忆有稳定编号 `mem-YYYYMMDD-NNN`；索引只存摘要，正文按主题拆分。
- 超出容量先归档到 `archive/<year>.md`，不删除、不重复编号。
- 外部条目用 `<provider>:<id>` 引用，正文留在外部；服务不可用时降级为摘要。
- 创建外部条目需用户明确授权。

## 写入时机

- 关键决策与取舍。
- 用户偏好或纠正。
- 缺陷根因与回归方式。
- 发布结果与已知问题。
- 任务中断时的交接信息。

## 检索顺序

1. 项目状态与决策。
2. 项目教训。
3. 外部记忆（若存在）。
4. 当前代码、测试与日志。

记忆是线索，不是证据。与当前事实冲突时以事实为准。

## 降级

没有外部记忆服务时，项目内 `.agent/` 必须完整可用：状态、决策、教训与长期记忆四类文件足以恢复上下文。不得因记忆缺失阻塞任务，也不得把记忆当作授权。

具体写入时机、格式与晋升规则见 `protocols/zh/memory.md`。

## 禁止

- 把项目名、路径、凭据或业务数据写入跨项目记忆。
- 用记忆覆盖用户当前修正。
- 把一次偶发事件直接记为通用规律。
