# 隔离验证环境

## 目标

让每次集成与端到端检查都有安全、可丢弃、可复现的环境，测试不再被生产风险阻塞。

## 隔离级别

| 级别 | 适用 | 限制 |
| --- | --- | --- |
| `container` | 运行时与依赖可打包；网络与数据可隔离 | 与宿主机共享内核与部分能力；硬件与特定系统行为可能不同 |
| `process` | 无容器运行时；临时端口、目录与数据足够 | 网络与文件系统隔离较弱；进程仍可能触达宿主机资源 |
| `virtual-machine` | 目标是不同操作系统、移动设备或需要真实系统行为的桌面平台 | 启动成本与许可证约束更高；反馈更慢 |
| `block` | 没有任何级别能达到所需保真度 | 不声称 E2E 通过；列出不可验证项 |

## 隔离对象

| 对象 | 要求 |
| --- | --- |
| 数据 | 合成或可丢弃；禁止复制生产数据 |
| 网络 | 默认拒绝外联；只放行声明的测试依赖 |
| 凭据 | 只用测试值；禁止生产密钥 |
| 外部服务 | 本地 mock、stub 或录制夹具；每次运行重置状态 |
| 操作系统与设备 | 平台行为重要时使用模拟器、仿真器或虚拟机 |
| 硬件 | 声明不可用硬件，阻塞依赖它的检查 |
| 时间与随机 | 测试依赖时固定或控制 |

## 安全不变量

- 创建前检测生产端点、凭据与数据集；命中即中止。
- 不对非隔离数据库执行迁移或破坏性命令。
- 使用临时端口、目录、卷与网络；不占用共享资源。
- 结束时拆除并做残留检查。
- 保留证据：命令、日志、测试输出与隔离边界。

## 选择顺序

1. 运行时与依赖可打包、网络与数据可隔离时，优先 `container`。
2. 无容器运行时，但临时资源足够时，使用 `process`。
3. 目标系统、设备或平台行为无法用前两者复现时，使用 `virtual-machine`。
4. 保真度不足时 `block`；列出不可验证项，不削弱测试。

## 输出

写入 `.agent/sandbox.md`：

- 选择的级别、原因与被否决的方案。
- 隔离了什么、模拟了什么、哪些仍是真实环境。
- 启动、灌数据、验证、拆除命令。
- 保真度限制与无法运行的检查。
- 最近一次运行的证据与残留检查。

## 降级

| 缺少 | 动作 |
| --- | --- |
| 容器运行时 | 进程级隔离，使用临时端口、目录与数据 |
| 模拟器或虚拟机 | 阻塞设备相关检查；列出人工检查项 |
| 外部服务 mock | 使用本地 stub 或录制夹具；仍不可行时阻塞该路径 |
| 任何隔离 | 不对生产运行测试；阻塞并记录原因 |

## 反例

- 因为方便就把测试指向共享预发数据库。
- 把生产数据复制到本地环境。
- 进程级运行仍能触达生产端点，却称为“完全隔离”。
- 测试只跑 mock、没有覆盖真实边界，却报告 E2E 通过。
