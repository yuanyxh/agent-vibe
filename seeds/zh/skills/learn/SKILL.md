# 自学习

## 目标

让同类问题不重复发生，同时避免把偶发经验上升为通用规则。

执行前读取 `.agent/rules/documentation.md`；文件不存在时跳过并说明。

## 代码健康扫描

在缺陷、重构、发布、评审或用户显式要求代码健康时运行。使用现有静态检查、测试与项目搜索；每条发现必须有 `file:line` 或命令输出。

| 维度 | 检查 |
| --- | --- |
| 架构 | 循环依赖、分层越界、依赖方向不稳定、领域逻辑重复、泄漏抽象、上帝模块 |
| 反模式 | 上帝对象、依恋情结、基本类型偏执、过长参数、复制粘贴、魔法数字、吞异常、时序耦合、布尔标志参数 |
| 死代码 | 未使用的文件、导出或依赖；不可达分支；注释掉的代码；过期特性开关；孤儿资源或配置 |

- 区分证据与怀疑，标注置信度。
- 每条发现归入新教训、backlog 项或重构任务。
- 本技能不执行重构或删除；删除移到废纸篓或归档。

## 步骤

1. **收集事实**：本次会话的缺陷、返工、发布问题或用户纠正，附证据。
2. **扫描代码健康**：触发条件成立时运行上述三个维度；记录 `file:line`、严重度与置信度。
3. **判定适用范围**：项目特有、技术栈相关或跨项目通用。
4. **写入项目**：项目特有的教训写入 `.agent/lessons.md`，格式为场景、事实、决策、适用范围。
5. **提议晋升**：跨项目模式按 `protocols/zh/distill.md` 判断，形成种子候选并交用户确认。
6. **去重**：与已有教训或规则同义时合并，不重复记录。

## 完成条件

- 每条教训可追溯到一次具体事件。
- 每条代码健康发现都有证据、严重度、置信度与去向。
- 通用候选未经用户确认不写入种子库。

## 禁止

- 记录没有证据的猜测。
- 用反模式名称替代证据。
- 自动重构或删除代码；删除移到废纸篓或归档。
- 把项目名、路径、凭据或业务数据写入通用种子。
- 自动修改 `seeds/zh/`。
