# 迭代开发

## 前置检查

- 当前目录必须有 `.agent/profile.yaml`；缺失时先执行 `init`，不得直接写代码。
- 若当前目录是种子仓库，停止并切换到目标项目。
- 基座的规则、技能与契约必须非空；空目录视为未初始化。
- 分支预检（`delivery.vcs` 为 `git` 时）：按 VCS-07 读取 `delivery.branch_strategy` 与 `delivery.trunk_branch`，运行 `git status --porcelain` 与 `git branch --show-current`；工作区不干净时先确认改动归属，禁止直接开始编码。

## 目标

把一项明确的需求变成可运行、可回滚的小增量，并保持项目状态可追溯。

## 规则读取

执行前读取 `.agent/rules/engineering.md`、`design.md`、`vcs.md`、`testing.md`；文件不存在时跳过并说明。

## 步骤

1. **读取状态与分支预检**：读 `.agent/status.md`、链接的计划、`.agent/backlog.md` 与相关规则，确认当前目标、进行中任务、约定与阻塞；`delivery.vcs` 为 `git` 时按 VCS-07 建立或确认任务分支，禁止在主干或无关分支上直接开发。`feature-branch` 策略从最新主干创建 `<type>/<task-slug>`；`trunk` 策略确认已在最新主干。
2. **定义增量**：选一个能在单次会话内完成并验证的最小切片。多步骤或跨会话任务在编码前把 `.agent/plans/_template.md` 复制为 `.agent/plans/<task-slug>.md`，并按 CTX-04 填写非目标、验收、已确认约定与有序步骤。范围不清时先拆解，不猜需求。按 REQ-01 区分目标与示例，范围确认时列出非目标；存在多种合理解读时按 REQ-05 记录候选取舍。
3. **检索复用**：新建模块、函数或组件前，用项目检索手段（全文搜索、依赖图、导出清单）查找职责相同的既有实现与调用方；有可用实现则复用或扩展，无则在交付摘要说明新建理由。
4. **实现**：遵循当前阶段匹配的规则；只改与任务相关的文件。`quality.test_level` 为 `strict` 时按 TST-05 逐切片先失败测试；缺陷修复按 TST-02。
5. **自测**：运行项目声明的测试与构建命令；无法运行时说明原因。存在界面时，还要真实启动一次并取截图或等价断言，只跑构建不算自测。按 TST-07 标注证据级别；无法自测时按 TST-09 输出移交清单。验证数据写入系统临时目录，不落在项目内；确需落在项目内时，加入忽略规则并在结束后清理。
6. **工程化检查与计划对账**：运行画像声明的格式化、lint 与类型检查命令；任何一项未通过先修复再继续。把当前计划步骤的状态与证据写入计划；范围、顺序或验收有变化时按 CTX-05 记录。
7. **提交前检查**：确认 diff 只包含本次意图的变更，无生成物、凭据、本地配置与验证残留；按提交规范生成提交信息。
8. **提交**：提交、推送、改写历史均属需授权操作。用户未明确授权时，只给出提交建议与命令，不执行。
9. **更新状态**：把计划步骤标记完成并附证据，未完成事项移入 `.agent/backlog.md`，再在 `.agent/status.md` 记录进度摘要、下一步与阻塞；有决策则写入 `.agent/decisions.md`。步骤细节不复制进状态。
10. **交付**：给出变更摘要（含复用或新建结论）、验证命令与结果、提交状态、当前任务分支与合并/清理建议；合并与删除分支需授权。

## 完成条件

- 增量可运行，测试结果来自本次实际执行。
- 任务分支已按 VCS-07 建立或确认，起始工作区干净或改动归属已获用户确认。
- 格式化、lint、类型检查按画像要求通过。
- 工作区无验证残留，diff 只含本次意图的变更。
- 提交已按规范完成，或已明确给出待授权的提交建议。
- 状态文件与代码一致，计划步骤与实际证据一致，约定事项不存在于对话之外的唯一归属。
- 未引入未记录的依赖或配置变更。
- 新建共享单元前已检索既有实现，交付摘要能说明复用或新建理由。

## 禁止

- 一次实现多个互不相关的需求。
- 在主干或无关分支上直接开发任务；把用户未提交改动静默带入任务分支。
- 用“应该可以”代替实际运行。
- 覆盖或丢弃用户已有的未提交改动。
- 未检索就新建与既有实现职责重叠的单元。
- 在未确认的情况下执行不可逆操作。
