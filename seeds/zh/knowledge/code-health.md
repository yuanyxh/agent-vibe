# 代码健康

## 问题

代码通过一个个小决定腐化：依赖指错方向、捷径变成模式、分支不再可达。目标是在变更变贵之前，用证据发现它们。

## 架构信号

| 信号 | 证据 | 风险 |
| --- | --- | --- |
| 循环依赖 | 导入或调用图成环 | 变更双向传播；测试互相纠缠 |
| 分层越界 | 下层导入上层 | 业务逻辑依赖交付细节 |
| 依赖不稳定 | 稳定模块依赖频繁变化的模块 | 每次变更都波及核心 |
| 领域逻辑重复 | 同一规则在多个模块实现 | 修复分叉；数据不一致 |
| 泄漏抽象 | 调用方依赖内部细节 | 实现变更破坏调用方 |
| 上帝模块 | 一个模块承担无关职责 | 冲突多、评审慢、归属不清 |
| 分布式单体 | 服务必须一起发布 | 耦合仍在，运维成本上升 |

## 反模式

| 模式 | 证据 | 风险 |
| --- | --- | --- |
| 上帝对象 | 一个类或模块有大量无关方法与字段 | 难测试、难修改 |
| 依恋情结 | 方法使用别的对象的数据多于自身 | 职责放错位置 |
| 基本类型偏执 | 用裸字符串或数字承载领域含义 | 非法状态可被表示 |
| 过长参数 | 大量位置参数，尤其布尔值 | 调用点难读、易误用 |
| 复制粘贴 | 近似代码块只有小差异 | 修复漏掉副本 |
| 魔法数字 | 逻辑中出现无解释字面量 | 意图与影响不清 |
| 吞异常 | 空 catch 或忽略失败 | 缺陷静默 |
| 时序耦合 | 正确性依赖未在类型中表达的调用顺序 | 顺序缺陷反复出现 |
| 布尔标志参数 | 一个函数用标志切换两种行为 | 调用方与测试在内部产生分支 |

## 死代码

| 信号 | 证据 | 动作 |
| --- | --- | --- |
| 未使用文件或导出 | 无导入、引用或路由 | 确认动态加载后移到废纸篓 |
| 未使用依赖 | 清单存在但无导入或构建使用 | 确认工具链用途后移除 |
| 不可达分支 | 在声明类型或配置下条件不可能成立 | 简化或记录保留原因 |
| 注释掉的代码 | 大段禁用且无解释 | 从版本控制恢复；不要保留 |
| 过期特性开关 | 所有环境恒开或恒关 | 移除开关与一条分支 |
| 孤儿资源或配置 | 无构建、运行时或文档引用 | 确认后归档 |

## 证据标准

- 引用 `file:line`、命令输出或图结果。
- 区分检测与解释，标注置信度。
- 判定死代码前检查动态加载、反射、配置与外部入口。
- 模式名称本身不是证据。

## 取舍

- 短期重复可能比过早抽象更便宜；报告它，不强制修复。
- 上帝模块可能是迁移期的有意边界；记录退出条件。
- 死代码可能为兼容而保留；要求有明确归属与移除日期。

## 验证

- 依赖图无环，或每个环都有归属与计划。
- 修改一条业务规则不需要同步修改复制逻辑。
- 删除死代码不改变可观察行为；用测试或基线确认。
- 每个被接受的反模式都有理由与复查日期。

## 反例

- 修复缺陷时顺手重构，却没有行为基线。
- 因为文本搜索没命中动态加载就删除导出。
- 没有混合职责证据，就把所有长函数报告成上帝对象。
- 把模式名称当作发现。
