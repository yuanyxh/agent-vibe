# agent 维护

## 问题

agent 环境会在不破坏构建的情况下腐化：规则互相矛盾、技能不再触发、记忆与代码漂移、提示词描述旧项目、钩子静默失败、未使用资产占用上下文。这些都不会让测试失败，但会让 agent 随时间变得不可靠。

## 腐化模式

| 模式 | 证据 | 风险 |
| --- | --- | --- |
| 规则冲突 | 两条规则对同一情境给出不同行为 | agent 任意选择 |
| 规则或技能陈旧 | 审查日期过期、版本过旧、内容已被替代 | 错误指导继续存在 |
| 资产重复 | 两条规则或技能覆盖同一触发 | 浪费上下文、行为不一致 |
| 断引用 | 规则、技能或契约指向不存在的文件或资产 | 指令无法执行 |
| 预算超限 | 常驻内容或技能描述超过预算 | 后续内容被截断或忽略 |
| 钩子静默失败 | 钩子退出但没有暴露错误 | 维护看似执行，实际没有 |
| MCP 失败 | 服务不可用、认证过期或权限过窄 | 工具无声消失 |
| 记忆漂移 | 记忆与代码、决策或用户当前修正矛盾 | agent 重复过时事实 |
| 重复修正 | 同一用户修正或缺陷反复出现 | 缺少规则、技能或记忆 |
| 死资产 | 规则或技能从未被引用或调用 | 只有维护成本，没有价值 |
| 泄漏 | 资产中出现密钥、个人路径、主机名或内网地址 | 安全与可移植性风险 |

## 证据

- 文件与行号、命令输出、配置片段。
- git 历史中的重复修复、回退的决策、没有决策记录的频繁改动。
- 状态、决策、教训、backlog 与记忆中的未解决或被替代结论。
- 平台暴露的会话记录中的重复提示、被忽略的规则、错误技能选择。
- 确定性检查：计数、重复、引用、日期与密钥模式。

## 误报

- 技能可能很少调用但依然关键；判定死亡前先检查触发证据。
- 规则可能由文本搜索看不到的平台机制加载。
- 记忆条目可能是有意保留的历史；检查状态与替代关系。
- 钩子可能注册在项目之外；检查生效配置。
- 重复可能是有意的项目覆盖；检查优先级规则。

## 节奏

- 缺陷修复、发布、重构或用户修正后，有新证据时检查。
- 按固定节奏检查，活跃项目默认每周一次。
- 新增或删除规则、技能、提示词、钩子或 MCP 服务之前检查。
- 不要高于节流允许的频率；噪音提醒会被忽略。

## 验证

- 每条发现都有证据、严重度与建议动作。
- 已应用的变更都有用户确认与回滚路径。
- 被移除的资产可恢复。
- 过期报告恰好提醒一次；新鲜报告不提醒。
- 执行后，报告时间戳与 pending 状态与实际结果一致。

## 反例

- 没有核对平台级加载就删除未被引用的规则。
- 把“已提醒”当作“已完成检查”。
- 把业务代码腐化报告成 agent 环境腐化。
- 因为删除有风险就保留所有资产；应该归档。
