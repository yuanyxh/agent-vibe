# 可观测性

## 问题

系统出问题时，能在用户大规模感知前发现，并快速定位原因。

## 模式

- **结构化日志**：时间、级别、关联 ID、事件、关键字段；不写自由文本大段。
- **指标**：关键路径的成功率、延迟、吞吐与资源使用。
- **追踪**：跨服务传递关联 ID，能还原一次请求的完整路径。
- **错误上报**：崩溃与异常带堆栈、版本、环境与用户无关标识；去重与聚合。
- **用户轨迹**：关键操作序列，用于复现；采集需符合隐私要求。
- **告警**：每条告警有影响、判断依据与处理动作；无行动项的告警删除。
- **脱敏**：日志与追踪不记录凭据、令牌与个人敏感数据。

## 取舍

| 手段 | 成本 | 适用 |
| --- | --- | --- |
| 日志 | 存储高 | 细节与审计 |
| 指标 | 低 | 趋势与告警 |
| 追踪 | 中 | 跨服务定位 |
| 轨迹 | 隐私风险 | 复现用户问题 |

## 验证

- 人为制造失败后能在指标或日志中定位。
- 同一请求的日志可被关联 ID 串起。
- 告警能对应到处理步骤。
- 抽样日志中无敏感字段。

## 反例

- 只打日志，无关联 ID。
- 记录完整请求体与令牌。
- 告警无行动项。
- 采样率过低导致关键问题丢失。
