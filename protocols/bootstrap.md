# 基座生成协议

init 只负责把种子实例化为可开发的工程基座，不负责实现业务功能。

## 前置

- 画像已确认。
- 目标项目路径已确定，且与种子仓库分离。
- 领域最低必问项已覆盖。

## 产物清单

目标项目内必须实际存在且非空：

| 产物 | 判据 |
| --- | --- |
| `.agent/profile.yaml` | 必填字段完整 |
| `.agent/status.md`、`decisions.md`、`lessons.md` | 有初始内容 |
| `.agent/memory/README.md` | 存在 |
| `.agent/environment.md` | 有探测记录 |
| `.agent/research.md` | 有版本基线、实践清单、agent 资产盘点、来源与采纳/拒绝理由 |
| `.agent/domains/<name>.md` | 每个 domain 一份 |
| `.agent/knowledge/README.md` | 有主题与触发条件 |
| 规则文件 | 按 `protocols/loading.md` 分层落点，核心内联，其余可指出实际机制 |
| 技能文件 | 至少一个有效技能，头部只有平台字段，正文写明要读取的规则 |
| 启动契约 | 含常驻约束、加载策略、技能索引、工作循环、验证命令 |
| 工程化配置 | 格式化、静态检查、类型检查、忽略规则 |
| 项目骨架 | 可构建的最小结构，不含业务功能 |

## 顺序

1. 创建目标目录。
2. 写入状态、画像、记忆骨架。
3. 执行环境探测。
4. 按 `protocols/research.md` 写入最佳实践与 agent 资产盘点结论。
5. 生成项目骨架与工程化配置。
6. 生长能力与领域定义。
7. 按 `protocols/loading.md` 生成加载清单：每项内容的层、触发与机制。
8. 实例化规则与技能，逐文件写入，禁止只建目录。
9. 生成启动契约，只内联常驻内容与索引。
10. 校验全部非空、可执行且未超预算。
11. 输出基座清单，等待用户确认。
12. 用户确认后结束 init。

## 校验

- 用目录清单确认每个产物存在且非空。
- 检查研究：`.agent/research.md` 存在，外部事实有来源、版本与日期，采纳项有映射。
- 运行工程化命令：格式化检查、静态检查、构建。
- 检查技能头部只含平台识别字段，规则无种子元数据。
- 检查加载：常驻 ≤ 200 行，核心内联 ≤ 60 行，除核心外无无范围规则。
- 检查每个 on-demand 项都有实际机制；无原生机制时标记降级。
- 检查启动读取集合只含契约与状态文件。
- 任一失败先修复，不得进入结束确认。

## 结束

确认后明确输出：

```
基座已就绪：<目标路径>
后续开发请在该目录执行 build。
```

init 到此结束。禁止在 init 内继续实现业务功能或游戏逻辑。

## 禁止

- 只创建空目录而不写内容。
- 在种子仓库内直接开发业务项目。
- 把基座生成与业务开发混在一次执行中。
- 未确认基座就继续写功能代码。
