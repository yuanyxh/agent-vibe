# 生长协议

把抽象种子实例化为目标项目内容。

## 触发

| 触发 | 条件 |
| --- | --- |
| `on-init` | 项目画像 `profile.yaml` 所有必填字段已有值 |
| `on-signal` | 对话或代码中出现明确信号，且对应字段已确定 |
| `on-demand` | 用户或 agent 显式请求生成某类内容 |

上下文不足时停止，先提问。禁止用猜测值填充。

## 步骤

0. **选来源**：项目结构优先使用 `packs/` 中匹配的技术包；无匹配包时，按 `seeds/scaffolds/README.md` 的结构要求现场生成。两类来源都必须通过验证。
1. **匹配**：产物种子用 `applies_when` 对照画像，用 `requires` 检查前置字段；条件值支持 `a|b` 表示任一，`!x` 表示排除，未声明的维度视为不限制。能力种子用 `triggers` 判断是否进入。领域定义优先匹配 `seeds/domains/`，无匹配时按 `_schema.md` 现场生成，不视为失败。两者都不产出固定逻辑产物。
2. **排序**：先规则与文档，再技能，最后项目结构与配置；被依赖者优先。
3. **研究**：读取 `.agent/research.md`；缺失时先按 `protocols/research.md` 查证。产物依赖外部事实时（版本号、工具用法、平台支持范围、社区规范），以研究结论为准，禁止凭记忆写默认值。记录来源、版本与查询时间。
4. **实例化**：替换正文中的占位变量，删除不适用分支，保留判断标准。上下文未确定的维度不生成，登记为待生长。
5. **解析落点**：种子只声明逻辑产物（如 `rule/always`、`rule/path`、`rule/skill`、`skill/init`、`contract`、`state/status`）；由当前 `agent.platform` 对应的适配器按 `protocols/loading.md` 解析为物理路径。契约模板中的 `{{core_rules}}`、`{{loading_table}}`、`{{skill/<name>}}` 占位符同样按映射替换。种子内不得出现平台目录。
6. **剥离元数据**：写盘前删除种子的 `id/kind/version/updated/review_by/status/load/trigger/summary/applies_when/requires/grow/emits/verify`，只保留目标平台识别的字段与正文；`trigger` 转为启动契约中的读取条件。
7. **落盘**：按解析结果写入；已存在的文件不得覆盖，改为生成差异建议交用户确认。
8. **校验**：执行 `protocols/verify.md`；失败项不得静默跳过。
9. **登记**：在 `.agent/status.md` 记录生成清单、未生成项及原因、外部事实的来源与查询时间。

## 冲突规则

- 项目画像与种子默认值冲突时，以画像为准，并把差异写入 `.agent/decisions.md`。
- 两个种子产出同一逻辑产物时，后生成的必须合并，不得覆盖已有内容。
- 已存在的项目文件不得被覆盖。
- 种子层不得把某个产品、平台或版本写成默认值；产品名只能作为示例出现。

## 输出

生成结束输出三项：已生成、未生成及原因、下次可生长的内容。
