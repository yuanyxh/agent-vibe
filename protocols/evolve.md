# 演进协议

规则、能力与技能都有生命周期，必须能被复核、替代与废弃。

## 元数据

规则类种子必须包含：

| 字段 | 含义 |
| --- | --- |
| `version` | 整数，每次实质修改递增 |
| `updated` | 最后修改日期 |
| `review_by` | 必须复核的日期，默认三个月后 |
| `status` | active / deprecated / superseded |
| `load` | always / on-demand |
| `load_via` | path / skill / read，按 `protocols/loading.md` 维护 |

## 复核触发

- `review_by` 到期。
- 依赖或平台发生大版本变更。
- 发生事故、回归或用户纠正。
- 同类规则出现冲突。

## 复核动作

1. 核实规则是否仍与当前事实一致。
2. 一致则只更新 `review_by`。
3. 需要调整则递增 `version`，写清变更原因。
4. 被替代时标记 `superseded`，并指向新规则编号；不删除原文。
5. 不再适用时标记 `deprecated`，写清原因与替代方案。

## 禁止

- 静默删除规则或改写历史。
- 让过期规则继续以 active 状态参与生成。
- 未经用户确认把项目特定经验写入通用层。

## 输出

复核结果写入项目状态或种子仓库的变更记录，包含日期、结论与依据。
