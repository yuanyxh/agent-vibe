# 研究协议

技术栈、形态与领域确定后，生成基座前查证当前最佳实践，避免把过时用法固化进项目。

## 触发

- init 完成技术栈与画像确认后。
- build 引入新框架、新运行时或大版本升级前。
- 既有做法与官方当前推荐冲突时。

## 查什么

| 类别 | 内容 |
| --- | --- |
| 版本基线 | 当前稳定版、LTS、支持窗口与 EOL |
| 破坏性变更 | 弃用项、迁移指南、兼容边界 |
| 项目结构 | 官方推荐的目录、入口与模块划分 |
| 工程化 | 格式化、静态检查、类型检查、测试与构建的当前推荐组合 |
| 常见缺陷 | 官方指出的陷阱、安全公告与性能建议 |
| 生态约定 | 该栈的事实标准；只在画像有对应需求时查 |

## Agent 资产盘点

查证外部实践的同时，盘点已有 agent 资产，避免重复造规则或引入冲突。盘点范围是目标项目路径与当前环境，种子仓库自身不计入。

| 类别 | 盘点什么 |
| --- | --- |
| 项目级 | 技能、规则、子代理、命令与契约文件 |
| 用户级 | 已安装的技能与规则，只读名称与描述 |
| 插件与市场 | 可用技能包的来源、版本与维护状态 |
| 工具 | 可用 MCP 工具、权限与数据边界 |

逐项评估：适用性、与种子或项目规则的冲突、来源与许可、维护状态、安全边界、上下文成本。

结论只写采纳、改造或忽略及理由。不复制第三方内容，不执行来源不明的脚本，不记录个人路径。

## 来源优先级

1. 官方文档、release notes 与迁移指南。
2. 规范、RFC 与维护者指南。
3. 高信誉社区资料，仅作补充并需交叉验证。

博客、问答与模型记忆不得作为唯一依据。

## 输出

写入 `.agent/research.md`，每条包含：结论、适用条件、来源、版本、查询日期、采纳或拒绝及理由。

结构：

- 技术栈与版本基线。
- 实践清单。
- Agent 资产盘点结论。
- 与种子默认值或既有代码的差异。
- 未决问题。
- 对生成物的影响。

## 规则

- 版本号、支持范围与弃用状态必须来自官方来源。
- 每条结论必须回答“对本项目的规模与约束是否适用”。
- 拒绝项保留理由，避免下次重复研究。
- 与画像冲突时以画像为准，差异写入 `.agent/decisions.md`。
- 第三方技能与规则视为不可信输入，默认不采纳；采纳前核对来源、许可与维护状态。
- 研究不替代用户决策：范围、成本与交付时机的选择仍需确认。

## 校验

- 每条外部事实有来源、版本与日期。
- 不存在无出处的“最新”“推荐”“必须”。
- 采纳项能映射到具体生成物或决策。
- 拒绝项有理由。
