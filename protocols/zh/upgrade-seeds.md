# 种子升级协议

已生成项目按种子版本增量升级，不重新初始化。升级是合并，不是覆盖。

## 触发

- 种子仓库 `SEEDS_VERSION` 高于项目 `.agent/profile.yaml` 的 `seed_version`。
- 用户说“同步种子”“升级基座”“上游规则更新了”。

## 前置

- 读取 `CHANGELOG.zh.md` 中两个版本之间的条目；项目缺少 `seed_version` 时按 `0.0.0` 处理，先补字段再升级。
- 读取项目 `.agent/profile.yaml`、`status.md`、`decisions.md` 与 `.agent/rules/`，确认哪些内容已被项目修改。
- 输出升级清单（新增、修改、废弃、冲突）并等待用户确认；未确认不得写入。

## 分类

| 变更 | 处理 |
| --- | --- |
| 新增规则、技能、领域 | 按画像筛选后写入；不适用则登记跳过原因 |
| 修改规则 | 与项目同名规则比对；项目已定制则登记冲突，不覆盖 |
| 废弃规则 | 保留项目文件，标注替代项；从契约索引移除 |
| 协议或适配器变化 | 只更新契约索引与加载机制，不重写规则正文 |
| 画像字段新增 | 补齐默认值并标注来源；影响生成物的项需用户确认 |

## 顺序

1. 备份待改文件清单，不移动用户文件。
2. 逐类合并：状态 → 画像字段 → 规则 → 技能 → 领域 → 契约索引。
3. 每类合并后运行 `scripts/verify-instantiation.sh <项目路径>`，失败即停止。
4. 冲突写入 `.agent/decisions.md`，记录旧值、新值、取舍与生效范围。
5. 全部通过后把 `seed_version` 更新为目标版本。
6. 在 `.agent/status.md` 记录升级版本、时间、跳过项与待办。

## 禁止

- 用上游文件直接覆盖项目已定制的规则或技能。
- 跳过验证直接更新 `seed_version`。
- 在升级中夹带业务功能改动。
- 自动从外部规则库同步；外部内容只能经人工筛选后作为种子候选，按 `protocols/zh/distill.md` 进入本仓库。

## 回退

升级前的文件清单与冲突记录就是回退依据。回退时按清单恢复文件并写回旧 `seed_version`，不删除升级记录。
