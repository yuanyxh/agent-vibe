# 环境探测协议

## 时机

- 新项目初始化。
- 新机器、新会话或换 Agent 环境。
- 依赖安装、构建或测试命令失败。
- 项目声明的运行时版本发生变化。

## 步骤

1. **读取声明**：项目画像、版本文件、构建配置中的要求。
2. **探测**：按运行时、包管理器、构建测试、版本控制、诊断、容器与托管的顺序执行只读命令。
3. **判定**：记录为可用、部分可用或缺失，附版本与命令输出摘要。
4. **选择替代**：优先使用已有工具；其次使用语言内置能力；最后才建议安装。
5. **登记**：写入 `.agent/environment.md`，包含时间、平台、工具、状态、替代与影响。
6. **校验**：确认项目声明的质量门在当前环境可执行，或明确哪些无法执行及原因。

## 降级规则

| 缺失项 | 首选替代 |
| --- | --- |
| 容器运行时 | 本地进程或构建产物冒烟 |
| 浏览器自动化 | 单元测试与构建检查，登记 E2E 未执行 |
| 托管 CLI | 本地 git 操作，登记远程步骤未执行 |
| 外部记忆服务 | 项目内 `.agent/` 文件 |

## 刷新

环境变化、命令失败或新会话开始时重新探测；旧记录保留时间戳，不覆盖历史结论。

## 脱敏

- 只记录可复现所需的最小信息。
- 主机名、内部地址、个人路径、账号不写入；需要时使用 `<host>`、`<registry>` 占位。
- 内网镜像只记录“使用环境代理或私有源”，不记录地址。
- 环境记录属于项目内文件，不得直接进入种子库或跨项目记忆。

## 禁止

- 用猜测替代探测。
- 把一次环境的结论写成所有环境的事实。
- 在未授权时安装工具或改变系统配置。
