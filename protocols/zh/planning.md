# 计划协议

上下文有限且会丢失。计划、约定与待办必须落在文件里；对话只是写入它们的通道。

## 文件边界

| 文件 | 职责 | 排除 |
| --- | --- | --- |
| `.agent/status.md` | 当前目标、进度摘要、阻塞 | 步骤细节与偏移历史 |
| `.agent/plans/<task-slug>.md` | 当前任务的目标、步骤、约定、偏移、交接 | 无关的未来工作 |
| `.agent/backlog.md` | 未排期或延后事项、优先级、来源 | 当前任务步骤 |
| `.agent/decisions.md` | 持久决策与回退 | 步骤状态 |
| `.agent/memory/` | 长期事实与用户偏好 | 任务计划 |

一个事实只有一个归属；按路径或编号引用，禁止维护两份副本。

## 何时必须写计划

- 任务包含多个有依赖的步骤。
- 工作跨会话或可能中断。
- 用户确认了计划、范围或约束。
- 上下文窗口接近上限，或工作要交给另一个 agent。
- 任务需要改变已约定的验收标准。

单个可回退步骤可以不建计划文件，但要在 `status.md` 记录原因。用户已确认计划时，任何情况下都不得省略。

## 写入时机

1. **开工前**：把 `.agent/plans/_template.md` 复制为 `.agent/plans/<task-slug>.md`，再填写目标、非目标、验收、约定与有序步骤；每个步骤声明依赖与证据。`_template.md` 永不当作活动计划。
2. **每步完成后**：更新步骤状态并附证据（命令、文件或测试）。没有证据不得标记完成。
3. **发生偏移时**：追加偏移记录，不改写历史。范围与验收变更必须得到用户确认后才能继续。
4. **任务中断时**：填写交接区，写明最后完成的步骤与确切的下一步动作。
5. **任务完成时**：逐项对账；未完成事项移入待办；计划标记为 `done` 或 `abandoned`；更新 `status.md`。

## 偏移类型

| 类型 | 信号 | 处理 |
| --- | --- | --- |
| 范围 | 新需求、越界工作或需求被取消 | 停止，向用户确认，更新非目标与步骤 |
| 顺序 | 依赖或阻塞使原顺序失效 | 记录变更、重排、说明影响 |
| 验收 | 原验收标准不再可测或不再成立 | 先与用户确认替代标准再继续 |
| 上下文 | 从摘要或新会话恢复 | 读状态、计划与偏移记录，依据代码与测试重建，不猜测 |

偏移记录包含日期、类型、变更、原因、受影响步骤与决定。静默偏移正是本协议要防止的失败。

## 恢复顺序

1. 启动契约。
2. `status.md` 中的当前目标与计划链接。
3. 链接的计划，包括步骤与偏移记录。
4. 选择下一项任务时读 `backlog.md`。
5. 只有任务需要历史依据时才读决策与教训。
6. 代码、测试与日志作为证据。

计划是意图，不是证明。与当前代码、测试或用户当前修正冲突时，以当前事实与修正为准，然后修正计划。

## 容量与归档

- 单个计划不超过 120 行、15 个步骤；更大的工作拆成独立任务。
- 待办最多保留 100 条未完成事项；完成与放弃的行移入归档区。
- 计划超过 14 天未更新标记为 `paused`；恢复前先与用户确认。
- 已完成计划作为历史保留，不删除，也不复用其任务标识。

## 边界

- 计划不得覆盖用户当前修正。
- 架构决策写入 `decisions.md`，计划引用它。
- 步骤证据写在计划或交付摘要中，不在状态里重复。
- 待办不是许愿池：每个事项都必须有来源与优先级。

## 禁止

- 多步骤计划只留在对话里。
- 静默改变范围、顺序或验收标准。
- 没有证据就标记步骤完成。
- 同一事项维护在多个文件。
- 把已完成步骤继续当作未完成工作。
- 用计划为忽视更新的事实辩护。
