# 校验协议

生成后检查实例化结果是否可用。

## 种子仓库自检

改动 `seeds/zh/`、`protocols/zh/` 或 `adapters/zh/` 后执行 `scripts/check-format.sh`、`scripts/verify-seeds.sh --strict` 与 `scripts/test-fixtures.sh`。失败项先修复；`--strict` 将警告视为失败。

`scripts/verify-instantiation.sh <项目路径>` 校验一次真实生成的基座；`tests/fixtures/` 是回归样例，种子改动不得让样例退化。

## 通用检查

| 项 | 判据 |
| --- | --- |
| 路径存在 | 种子的 `emits` 全部落地 |
| 无占位残留 | 目标文件中不存在 `{{`、`TODO`、`<待填>` |
| 规则可执行 | 每条规则含触发条件与可观测验证方式 |
| 技能可触发 | 每个技能有 name、description 与明确的加载条件 |
| 契约完整 | 启动契约位于适配器指定位置，并列出常驻约束、加载策略、技能索引、工作循环与运行时约定 |
| 记忆可降级 | 无外部记忆服务时，`.agent/` 的状态、决策、教训与长期记忆足以恢复上下文 |
| 环境已探测 | `.agent/environment.md` 记录工具状态、替代与存疑项 |
| 知识可索引 | 项目存在知识索引，列明加载主题与触发条件，未整册注入 |
| 无平台残留 | 种子文件中不出现 `.claude/`、`.cursor/`、`CLAUDE.md` 等平台路径 |
| 状态可追溯 | `.agent/status.md` 记录已生成与未生成项 |
| 计划可追溯 | 多步骤任务链接 `.agent/plans/<task-slug>.md`；每个步骤有状态与证据；偏移记录有原因与影响 |
| 待办唯一 | `.agent/backlog.md` 存在；未完成事项有编号、优先级、状态与来源；同一事项不在状态或计划中重复 |
| 项目可构建 | 按画像声明的构建命令执行成功 |
| 工程化卡口 | 格式化、lint、类型检查命令按画像声明执行成功 |
| 钩子可执行 | `pre-commit` 与 `commit-msg` 存在且可执行，命令与 `verify.format` / `verify.lint` 一致 |
| PR 模板 | `repo_host=github` 时存在 PR 模板 |
| 版本控制就绪 | VCS 已初始化；忽略规则覆盖生成物、依赖、本地配置与验证数据 |
| 依赖已锁定 | 存在依赖时声明 `stack.lockfile` 且文件存在；`verify.install` 能按锁定文件可复现安装 |
| 依赖已审计 | 声明并执行 `verify.audit`，或在记录原因后填 `none`；高危项有修复或接受记录 |
| 升级扫描可追溯 | 声明 `verify.outdated`；`.agent/upgrades.md` 记录当前与最新版本、变更类型、推荐、理由与扫描日期 |
| 提交合规 | 已提交记录符合提交规范；未提交时说明原因与待授权动作 |
| 外部事实可追溯 | 版本号、平台支持范围、工具用法有来源与查询时间 |
| 研究可追溯 | `.agent/research.md` 存在；每条结论有来源、版本与查询日期；拒绝项有理由 |
| 实践已采纳 | 影响基座的结论已进入生成物，或已在决策日志登记 |
| Agent 资产已盘点 | 研究简报含盘点结论；采纳、改造与忽略均有理由；未复制来源不明内容 |
| 能力覆盖 | 每项声明能力的生成项或未生成原因已登记，无静默跳过 |
| 基座非空 | 画像、领域、环境、记忆、规则、技能、契约均存在且文件非空 |
| 无业务功能 | init 产物只含骨架与配置，不含业务模块或游戏逻辑 |
| 领域覆盖 | 每个 `project.domain` 有定义文件（种子库或项目内），`core_concerns` 逐项有生成项、测试或未覆盖原因 |
| 规则元数据完整 | 每条规则有 version、updated、review_by、status、load |
| 规则未过期 | `review_by` 晚于当前日期，或已完成复核并更新 |
| 加载策略一致 | `always` 只内联进契约；`on-demand` 按 `load_via` 落到路径、技能或显式读取；常驻未超预算 |
| 按需可触发 | 每条 `on-demand` 规则有 `load_via`，且对应机制存在 |
| 规则加载分层 | `path` 有可执行 `paths` 或 `globs`；`skill` 有技能正文指向；`read` 在契约中标记降级 |
| 无无范围规则 | 除核心外，没有会被平台每次会话加载的无范围规则文件 |
| 常驻预算 | 启动契约 ≤ 200 行；核心内联 ≤ 60 行 |
| 无常驻复制 | 契约未复制规则正文、完整画像、状态、决策或技能正文 |
| 启动读取集 | “开始任何任务前”只读契约与 `.agent/status.md`，不遍历 `.agent/` |
| 无全量机制 | 未用 `@import` 引入按需规则；未把非核心规则设为 `alwaysApply: true` |
| 无种子元数据残留 | 目标 `SKILL.md` 只有平台识别字段；规则文件无种子元数据，路径规则只保留平台字段 `paths` |
| 版本可追溯 | `.agent/profile.yaml` 含 `seed_version`，且等于生成时的 `SEEDS_VERSION` |
| 记忆可追溯 | `.agent/memory/INDEX.md` 存在，条目编号稳定，归档可按编号检索 |
| 实例化可回归 | golden fixture 通过 `scripts/verify-instantiation.sh`；种子改动不降低校验结果 |

## 冲突检查

- 同一主题不得存在两条互相矛盾的规则。
- 项目级规则与种子规则冲突时，必须有一处显式标注覆盖关系。
- 规则不得引用不存在的文件或技能。

## 失败处理

校验失败时列出失败项、原因与修复动作。存在失败项时不得宣布初始化完成。
