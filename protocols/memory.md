# 记忆协议

默认把记忆写入项目，外部记忆服务只作为可选增强。

## 位置

| 内容 | 位置 |
| --- | --- |
| 当前目标与进度 | `.agent/status.md` |
| 决策与回退 | `.agent/decisions.md` |
| 有证据的经验 | `.agent/lessons.md` |
| 长期事实、偏好与约束 | `.agent/memory/INDEX.md` 与 `.agent/memory/<topic>.md` |

## 写入时机

- 关键决策与取舍。
- 用户偏好或纠正。
- 缺陷根因与回归方式。
- 发布结果与已知问题。
- 任务中断时的交接信息。

## 写入规则

1. 一条记忆只写一个事实。
2. 每条有稳定编号 `mem-YYYYMMDD-NNN`，编号一经写入不复用。
3. 附来源：会话、命令输出、文件或测试。
4. 标注适用范围：仅本项目、本技术栈或可能通用。
5. 与已有条目同义时合并，不重复新增。
6. 被新事实推翻时标注取代关系，不删除历史。

## 条目格式

`.agent/memory/<topic>.md` 中每条记忆使用二级标题编号，正文不超过 5 行：

```markdown
## mem-20261029-001

事实：<一句话>
来源：<会话 / 命令 / 文件 / 测试>
范围：project | stack | universal
状态：active | superseded
取代：<mem-id，可选>
外部：<provider>:<id>，可选
```

`INDEX.md` 只保留一行摘要：

```
| id | 摘要 | 范围 | 状态 | 更新 | 所在文件 |
```

## 检索顺序

1. `.agent/status.md`
2. `.agent/decisions.md`
3. `.agent/lessons.md`
4. `.agent/memory/INDEX.md`，命中后再读对应主题文件
5. 外部记忆服务（若存在）

记忆是线索，不是证据。与当前代码、测试或用户说明冲突时，以当前事实为准。

## 容量与归档

- `INDEX.md` 活跃条目上限 100 行；超出时先归档，不继续追加。
- 归档条件：状态为 `superseded`，或更新超过一年且不属于当前范围。
- 归档移到 `.agent/memory/archive/<year>.md`，索引行同步标记 `archived` 并保留 id。
- 归档不删除内容；需要追溯时按 id 搜索归档文件。
- 同一主题文件超过 120 行时按子主题拆分，索引的“所在文件”列同步更新。

## 外部条目引用

外部记忆只存引用与摘要，正文留在外部服务：

- 首次写入外部条目必须获得用户明确授权，并记录服务名、条目 id 与写入时间。
- 本地条目的 `外部` 字段使用 `<provider>:<id>` 稳定引用；同一外部条目只能对应一个本地 id。
- 外部条目同样需要条目标题与摘要，便于服务不可用时降级。
- 外部服务不可用或条目被删除时，本地降级为摘要，不阻塞任务，并在 `status.md` 记录失联条目。
- 不得把项目名、路径、凭据或业务数据写入外部条目。

## 外部记忆

环境提供外部记忆服务时可以同步，但必须：

- 只写脱敏后的通用模式。
- 不写项目名、路径、凭据与业务数据。
- 外部服务不可用时，项目内记忆必须完整可用。

## 晋升

项目内反复验证的模式，按 `protocols/distill.md` 提议进入种子库；未经用户确认不得自动晋升。

## 禁止

- 用记忆覆盖用户当前修正。
- 把一次偶发事件记为通用规律。
- 让记忆成为任务执行的阻塞项。
