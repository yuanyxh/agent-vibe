# 加载协议

规则与持久化内容不按目录全量注入，按“是否每次任务都需要”分层，并落到目标平台的真实机制上。

## 四层

| 层 | 内容 | 进入上下文 | 预算 |
| --- | --- | --- | --- |
| L0 常驻 | 不可违反的底线、加载索引、验证命令 | 每次会话 | 契约 ≤ 200 行，核心 ≤ 60 行 |
| L1 路径 | 只与某类文件或目录相关的规则 | 碰到匹配文件 | 单文件 ≤ 120 行 |
| L2 任务 | 只在某类工作发生时需要的规则 | 对应技能被调用 | 单文件 ≤ 120 行 |
| L3 参考 | 领域、知识、决策、教训、环境、记忆 | 显式需要时读取 | 每次 ≤ 3 个文件 |

预算优先于规则完整性。超出预算时，把低频内容降到下一层，不压缩成更长的常驻文件。

## 规则种子字段

```yaml
load: always | on-demand
load_via: path | skill | read   # on-demand 必填
path_scope: source | ui | server | tests | config | domain
skills: [build, review]         # load_via=skill 时必填
```

- `always`：只允许核心底线。生成时每条压成一行摘要（编号 + 行为 + 禁止项）内联进启动契约，不再生成独立的无范围规则文件；完整正文留在种子层。
- `path`：生成时按 `path_scope` 映射为实际 glob，写入平台可识别的前缀。
- `skill`：规则文件放在逻辑位置，由对应技能正文要求执行前读取。
- `read`：平台无原生机制时的显式降级；必须在契约索引写明触发与路径，并标记 `degraded`。

## 路径范围

`path_scope` 在生成时按项目骨架解析为实际 glob，不写死在种子里。

| `path_scope` | 解析目标 |
| --- | --- |
| `source` | 源码目录，如 `src/**`、`apps/*/src/**`、`packages/*/src/**` |
| `ui` | 页面、组件与样式目录 |
| `server` | 服务端、API 与数据访问目录 |
| `tests` | 测试文件与测试配置 |
| `config` | 构建、格式化、静态检查与流水线配置 |
| `domain` | 领域定义指明的核心模块目录 |

解析为空说明该规则不适用于本项目，跳过并登记原因；不得留下无范围的 L1 规则。

## 平台矩阵

| 平台 | L0 | L1 | L2 | L3 |
| --- | --- | --- | --- | --- |
| Claude Code | `CLAUDE.md` 内联 | `.claude/rules/*.md` + `paths` | `.agent/rules/*.md`，由技能读取 | 索引 + 按需读取 |
| Cursor | `.cursor/rules/core.mdc`，`alwaysApply: true` | `.mdc` + `globs` | `.cursor/commands/<skill>.md` 引用规则 | 索引 + 按需读取 |
| Codex | `AGENTS.md` 内联 | 子目录 `AGENTS.md`；不支持时降级 | `.agents/skills/*/SKILL.md`，`$<name>` 调用；目录不可用时退回 `.agent/skills/` 并标记降级 | 索引 + 按需读取 |
| 通用 | `AGENTS.md` 内联 | 无原生机制时降级 | 索引 + 读取 | 索引 + 读取 |

平台没有原生机制时，不得声称“按需加载”，必须在契约中标记降级方式。

## 持久化内容

默认都不进入常驻，除下列例外：

| 内容 | 层 | 读取时机 |
| --- | --- | --- |
| 画像摘要（名称、形态、技术栈、质量预算） | L0 | 内联到契约 |
| `.agent/status.md` | L3 | 每次任务开始时读一次，只读当前目标与阻塞 |
| `.agent/decisions.md`、`lessons.md` | L3 | 需要历史依据或复盘时 |
| `.agent/environment.md` | L3 | 安装、构建失败或换环境时 |
| `.agent/domains/*.md` | L3 | 涉及该领域关注点时 |
| `.agent/knowledge/*.md` | L3 | 按索引命中，每次 1~3 篇 |
| `.agent/memory/` | L3 | 需要跨会话结论时 |

完整画像、决策与教训全文不得复制进契约。

## 生成要求

1. 先生成加载清单：每项内容属于哪一层、触发条件、目标机制。
2. 只把 L0 写入常驻文件；核心内联块用 `<!-- core:start -->` 与 `<!-- core:end -->` 包裹，块内 ≤ 60 行；L2 规则由技能正文指向，不复制。
3. L1 必须有可执行的匹配范围；范围为空视为 L0 或 L3，不得留在 L1。
4. L2 的 `skills` 必须全部存在；缺一个则不生成该规则并登记原因。
5. 契约中的索引只写路径、触发与机制，不写规则正文。
6. 生成后核对实际加载结果：Claude Code 用 `/context` 查看 Memory files；其他平台按其机制核对。

## 禁止

- 无 `paths` 的规则文件除核心外进入 `.claude/rules/`。
- 用 `@import` 引入按需规则；导入与引用文件同时加载。
- 把技能正文复制进契约或规则文件。
- 启动时遍历读取 `.agent/`。
- 在平台不支持时用“索引”冒充原生按需加载而不标记降级。

## 验证

- 常驻文件行数与核心行数在预算内。
- 每个 on-demand 项都能指出实际加载机制与触发条件。
- 启动读取集合只含契约与状态文件。
- 删除任一按需文件后，对应触发条件下会出现明确缺失，而不是静默失效。
